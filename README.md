# Jumbo

An AI wellness and longevity companion. Jumbo connects the health data you
already have, fills the gaps a wearable cannot see, explains what is changing,
and shows what your current patterns could mean for the life you actually live.

> Jumbo is a wellness, performance and longevity companion. It is not a
> diagnostic tool or a medical device, and its projections are not clinical
> predictions.

---

## What is real, and what is not

This is the first thing to read, because it is the thing most health demos are
dishonest about.

| Capability | Status |
|---|---|
| **Device camera** | Real. Opens the actual camera, live preview, capture, retake, front/rear, or choose an existing photo. |
| **Meal analysis** | Real. The captured JPEG goes to the Claude API, which returns identified foods with per-item confidence, portions and macros. Requires `ANTHROPIC_API_KEY`. |
| **Ask Jumbo** | Real. A conversation endpoint that answers from a statistical summary of your own records, keeps context across the thread, and refuses to diagnose or predict a lifespan. Requires `ANTHROPIC_API_KEY`; without one the composer is disabled and says why. |
| **Phone verification** | **Partly real.** The six-digit flow, masked number and resend timer are real; there is no SMS provider wired in, so Jumbo generates the code on the device and shows it, saying plainly that it did not send you a text. |
| **Voice log** | Real where the browser supports the Web Speech API, and hidden where it does not. Dictation is the browser's, not a Jumbo service. |
| **Pattern insights** | Real, two ways. With a Claude key, a statistical summary of your data is analysed by the model. Without one, Jumbo's own statistics run in the browser. The UI always says which. |
| **Future scenarios** | Real. The projection model runs locally; the written scenario is generated by Claude. Requires `ANTHROPIC_API_KEY`. |
| **WHOOP · Oura · Fitbit · Withings · Garmin** | Real OAuth 2.0, completed server-side with PKCE where the provider requires it, then real API reads and normalisation. Requires that provider's client ID and secret. |
| **Apple Health · Health Connect** | **Cannot work in a browser.** They are platform SDKs with no web API. Jumbo shows exactly why and connects them through a native bridge in the app shell. See `docs/NATIVE.md`. |
| **YouTube** | Real YouTube Data API v3 search, channels, durations and view counts, with an embedded player. Requires `YOUTUBE_API_KEY`. Jumbo never invents a creator or a video. |
| **Reminders** | Real Notification API, scheduled in-page. A browser cannot fire a notification while it is closed, and Profile says so rather than promising otherwise. |
| **Sample data** | A deterministic six-month history so the product is explorable immediately. **Always labelled "Sample data"** and never presented as a health record. |
| **Artwork** | **Placeholders.** The mascot, avatars, illustrations, brand mark and source logos are marked stand-ins in `public/assets/`, sized to the slots they will fill. Replacing one is a file copy — see `docs/ASSETS.md`. |

Nothing is faked to look connected. Every capability that is not configured
shows a specific notice naming the environment variable it needs and linking
the provider's documentation.

## Running it

```bash
npm install
cp .env.example .env      # fill in whatever you have; blanks are fine
npm run dev               # web on :5173, API on :8787
```

- `npm run dev:web` — the app alone. It detects the missing API and drops to
  clearly labelled demo mode.
- `npm run dev:api` — the server alone.
- `npm run build` — type-check and production bundle.

With an empty `.env` the whole app still runs: onboarding, the camera, the
model, the charts and the sample history all work. The AI, YouTube and the
health integrations announce that they are off.

### Turning things on

Every variable is documented in `.env.example`. The short version:

| To enable | Set |
|---|---|
| Meal analysis, insights, future scenarios | `ANTHROPIC_API_KEY` |
| Explore | `YOUTUBE_API_KEY` |
| Serving artwork from somewhere other than `public/assets` | `VITE_ASSET_BASE_URL` |
| Ask Jumbo | `ANTHROPIC_API_KEY` (the same key) |
| A health source | `<PROVIDER>_CLIENT_ID` and `<PROVIDER>_CLIENT_SECRET`, and register `{PUBLIC_URL}/api/oauth/callback/{provider}` as the redirect URI |

Garmin issues its Health API endpoints with programme approval, so
`GARMIN_AUTHORIZE_URL`, `GARMIN_TOKEN_URL` and `GARMIN_API_BASE` must be
supplied too. Jumbo does not guess them.

## The screens

| | |
|---|---|
| **Today** | A day selector, four animated rings around one health score, the day's state in a sentence, Jumbo's read of it, four key numbers you can open, a way into the conversation, and three things worth finishing. Choosing another day changes all of it. |
| **AI Future** | Jumbo greets you and offers real questions. Then the numbers it holds, a longevity outlook over 1, 3 or 5 years with the Jumbo Index, what it recommends, and the scenario model underneath — as a curve, a written story, and numbers with their uncertainty. |
| **Ask Jumbo** | The conversation. Grounded in your data, generating and error states, retry, suggested follow-ups, and a send button that stays dormant until there is something to send. |
| **Capture** | Camera-first meals, workouts with perceived effort, measurements, notes, dictation where the browser allows it — all written to the day you have selected. |
| **Explore** | Real YouTube: a featured video, a trending row, sortable recommendations, save and follow. Kept explicitly separate from Jumbo's own guidance. |
| **You** | Photo, name and phone, goals, sources, reminders, haptics and sound, privacy, export, delete. |

Onboarding is fourteen short screens: welcome, your details, verification, goals,
sources, permissions, sync, what Jumbo learned, its first insight, an
introduction to the AI, a look at the Future screen, the celebration, reminders,
and a final checklist.

Measurements sits one tap from Today and in the desktop sidebar.

## How it is put together

```
server/                 Express API. Credentials live here and never reach the browser.
  lib/providers.js      The integration registry, including what each one still needs
  routes/oauth.js       Real OAuth 2.0 with PKCE, signed state, token refresh
  routes/health.js      Per-provider adapters and normalisation
  routes/ai.js          Claude vision, insights and future scenarios (forced structured output)
  routes/youtube.js     YouTube Data API v3

src/
  components/Camera.tsx Real getUserMedia capture with every failure state handled
  lib/api.ts            One typed client; every call returns ok / setup / offline / error
  lib/native.ts         The JumboNative bridge contract for HealthKit and Health Connect
  lib/trajectory.ts     The projection model and its stated assumptions
  lib/analytics.ts      Baseline, daily state, on-device pattern engine, Claude summary
  lib/feedback.ts       Haptic patterns, synthesised sound, confetti
  lib/reminders.ts      Notification scheduling
  screens/              Today, Future, Capture, Explore, Measurements, You
```

No UI framework and no chart library. Every ring, sparkline, day curve and
projection band is hand-built SVG, so the visual language stays consistent and
the bundle stays small (~95 kB gzipped).

### The sample history is deliberately imperfect

`src/data/generate.ts` builds 182 correlated days from a seeded PRNG. Signals
influence each other the way they do in life: late bedtimes depress overnight
HRV, hard sessions raise the next morning's resting heart rate, rest days
restore it. It encodes three real stories for the pattern engine to find — a
cluster of late nights, a training-load ramp, protein below a common reference —
so the insights are genuinely present in the data rather than scripted.

### The model is inspectable

`src/lib/trajectory.ts` applies documented directional relationships to *your*
baseline and widens its uncertainty band with the horizon. Every assumption is
listed in the UI under "What the model assumes", including what it does not
model at all.

## Design

Built against Apple's Human Interface Guidelines, applied as cross-platform
principles.

- **Dark-first, and honestly so.** The brand colour `#92E82A` reads at 13:1 on
  near-black and 1.5:1 on white. Dark is the product; light mode is fully
  supported and swaps the green for a darker ink-green wherever it carries text.
- **One accent, one radius system, 8-point spacing.** Controls are pills, cards
  are 20px, inputs are 12px, everywhere.
- **Six health dimensions, six controlled accents.** Sleep, movement, nutrition,
  recovery, training and measurements each own a colour, all at 5:1 or better
  against their surface.
- **Motion is opt-in per icon and tied to meaning.** Sleep breathes and the heart
  beats only where they represent a live state. The AI orb pulses only while a
  request is genuinely in flight. Nothing loops for decoration, and everything
  stops under `prefers-reduced-motion`.
- **Provenance is always visible.** *Measured*, *Evidence-informed* and
  *Model estimate* separate what was recorded from what research suggests from
  what Jumbo computed.
- **No AI claim without a confidence and a stated limitation.** Low-confidence
  meal recognition says so and says why.
- **Haptics, sound and confetti are reserved for real completions** — a capture,
  a confirmed meal, a finished workout, a milestone. Never on ordinary taps.
  Both have their own switch, because browsers cannot read a silent switch.
- **Rest counts.** The movement target relaxes on a rest day and the consistency
  streak carries one grace day. No badges, points or leaderboards.
- **Never fear-based.** No mortality countdowns, no disease risk, no
  deterministic claims. The Future screen speaks in ranges and conditionals.
- **Accessibility.** Body text at or above 4.5:1 in both themes, every control at
  least 44pt, focus trapping in sheets, labelled charts, and a live region on
  every asynchronous state.
- **The profile photo is always top right** on every top-level screen, and
  never on the left. Tapping it opens You; tapping it there changes the photo,
  which is cropped and kept on the device alone. The Home storyboard shows the
  avatar on the left; the written specification overrules it twice, so the
  specification wins.
- **Four rings, four named colours.** Sleep violet, movement mint, food amber,
  recovery blue, with the brand green reserved for the overall score, selected
  states and primary actions. Training keeps its coral so it never reads as a
  fifth ring.
- **Artwork has reserved slots, not improvised ones.** Every image is declared
  once in `src/lib/assets.ts`, drawn into a slot with a fixed size and aspect
  ratio, and collapses to a plain surface if the file is missing. Finished
  artwork drops in without moving a single pixel of layout.

## Known boundaries

- Sessions and provider tokens are stored in a small JSON file. Swap
  `server/lib/store.js` for a real database before this handles anyone's data
  for real.
- Provider endpoint paths follow each vendor's published Web API and are
  overridable by environment, because vendors move them. Each adapter reports a
  structured error rather than inventing a value.
- Reference ranges beside biomarkers are commonly cited figures for context
  only; they vary between labs and guidelines.
- The Future model is a transparent approximation, not a validated clinical
  instrument. Read the direction, not the decimal.
